# measComp TC-32 Channel Count Fix

The record of the first run of `upstream-fix-verification-procedure.md`,
made before `tools/verify_fix_build.bash` and `tools/pv_snapshot.bash`
existed. The steps below are listed in the order they were run. Follow the
procedure for a new run.

## Defect

`MultiFunction::MultiFunction()` in `measCompApp/src/drvMultiFunction.cpp`
takes the thermocouple channel count from
`ulAIGetInfo(AI_INFO_NUM_CHANS_BY_TYPE, AI_TC)`. uldaq returns 64 for every
TC-32 and E-TC32, with or without the EXP-32 expansion. Without the
expansion, the poller calls `ulTIn` for channels 32-63, and each call fails
once per poll cycle:

```
MultiFunction::pollerThread Error: Calling TIn, err=14 Invalid analog input channel specified
```

Readings on channels 0-31 are correct. The defect is log noise.

## Fix

For `boardFamily_ == USB_TC32` (the USB TC-32 and the Ethernet E-TC32), the
constructor calls `ulDevGetConfig(DEV_CFG_HAS_EXP)` and halves the count when
the call succeeds and reports no expansion. Any other outcome leaves the
count unchanged. The change is 7 lines, on the Linux path only.

5. Before the window: built `tools/tc32-expansion-query.cpp` on the host.
   `ldd` resolved `libuldaq.so.1` from `<tree>/vendor/lib`, and a run with an
   unused identifier exited 3.
6. Captured the baseline from the running production IOC.
7. Stopped the production IOC. The query on the unit returned `has_exp=0`.

    0.0384 C; the 25 unpopulated channels and all alarm limits were
    identical. The difference was accepted as ambient variation.
11. Stopped the copy and restarted the production IOC; it served as before.
    The IOC information export named the production measComp again.
12. 2026-09-23: opened upstream pull request epics-modules/measComp#39.

## Result

Pass on an E-TC32 without EXP-32 (firmware 1.08). The 64-input path with
EXP-32 is not hardware-verified; no such unit exists at this site. The
register entry is `docs/milestone-1.4.0.md` M12 at commit `84ee626`. Host names, device
identifiers, PV names, and the evidence files stay in the site's private
record.

EPICS-env carries the fix until the pin moves past the upstream merge.
